# Grade Garden 🌷

[เปิดเว็บ](https://grade-garden.vercel.app) · [GitHub](https://github.com/aonchalisa/GradeGarden)

คำนวณ GPA รายเทอมและ GPAX พร้อมบัญชีส่วนตัวและบันทึกข้ามอุปกรณ์

## ใช้งาน

1. สมัครด้วยชื่อผู้ใช้ 3–24 ตัว (a–z, ตัวเลข, _) และรหัสผ่านอย่างน้อย 4 ตัว
2. แต่ละบัญชีมีแผนของตัวเอง บันทึกออนไลน์อัตโนมัติ เปิดต่อจากอุปกรณ์อื่นด้วยบัญชีเดิมได้
3. เลือกเกรดบนการ์ด หรือกดชื่อวิชาเพื่อแก้ชื่อ รหัส หน่วยกิต หมวด และเทอม
4. ลากการ์ดเพื่อย้ายวิชา/ลำดับในเทอมได้ บนมือถือย้ายด้วยช่องเลือกเทอม
5. เพิ่มวิชาและเทอม ปรับขั้นต่ำรายหมวดและยอดรวม และลงเกินขั้นต่ำได้
6. ตั้งเป้าเกียรตินิยมอันดับ 1 (GPAX 3.60) / อันดับ 2 (3.25) และดู GPA เฉลี่ยที่ต้องทำในหน่วยกิตที่เหลือ ตั้งจำนวนเองหรือใช้จำนวนตามแผนได้ เป้าที่เลือกและจำนวนที่กำหนดเองเซฟข้ามอุปกรณ์
7. กรองวิชาตามหมวดใหญ่ บังคับเรียน (ศึกษาทั่วไป+พื้นฐาน+แกน), บังคับเลือก (เทคโนโลยีสารสนเทศ), ศตวรรษที่ 21, วิชาเลือก, เลือกเสรี และยังไม่จัดหมวด ใช้ร่วมกับปีและค้นหาได้ GPA/GPAX ยังคำนวณจากทุกวิชา
8. สำรอง/นำเข้าแผนเป็น JSON ได้

สมาชิกใหม่เริ่มด้วยแผน CP 2022 ตามภาพสี 52 รายการ รวม 138 หน่วยกิต เกรดว่างทั้งหมด ไม่มีวิชาปิดตา ไม่มีซัมเมอร์ และ GenEd 4 ช่อง ไม่มีข้อมูลเกรดส่วนตัวใน repository นี้ ดู [รายวิชาทุกเทอมและหมวดตามสี](DEFAULT_PLAN.md) การเปลี่ยนค่าเริ่มต้นนี้ไม่เปลี่ยนแผนที่บัญชีเดิมเซฟไว้

เมื่อเน็ตหลุด ฉบับร่างจะเก็บในเครื่องและแสดงว่ายังไม่บันทึกออนไลน์ เมื่อกลับมาออนไลน์จะลองบันทึกใหม่ ถ้าแก้พร้อมกันจากหลายเครื่องจะหยุดการบันทึกที่ขัดแย้ง ให้สำรองฉบับร่างแล้วโหลดแผนล่าสุดก่อนแก้ต่อ

ระบบเริ่มต้นใช้ **ชื่อผู้ใช้และรหัสผ่าน** ไม่ขออีเมลจริง จึงไม่ต้องรออีเมลยืนยัน และ **ยังไม่มีการรีเซ็ตรหัสผ่านทางอีเมล** ควรเก็บรหัสผ่านใน password manager

## สถาปัตยกรรม

- Vite + JavaScript; Vercel เชื่อม GitHub main เพื่อ deploy อัตโนมัติ
- Supabase Auth จัดการ password hashing/session/refresh token
- Username แปลงเป็นที่อยู่ภายในโดเมนสงวน `.invalid` ไม่ใช่อีเมลจริงหรือการรับรองตัวตนผ่านอีเมล
- PostgreSQL `study_plans` เก็บแผนหนึ่งรายการต่อ user ID
- Row Level Security (RLS) ตรวจ UUID จาก session ทั้งอ่านและเขียน
- ฟังก์ชัน `save_study_plan` ใช้ revision เพื่อป้องกันการทับกันจากแท็บเก่า
- ใช้ publishable key ในเบราว์เซอร์ ไม่ใช้ service_role key ในแอป

## ตั้งเว็บใหม่บน Vercel/Supabase

1. สร้าง Supabase project แล้วรันไฟล์ migration ทั้งไฟล์ครั้งเดียว
2. ตั้ง Auth ตาม `supabase/config.toml` สำหรับ username mode
3. Import GitHub repository บน Vercel; Framework **Vite**, Build `npm run build`, Output `dist`, Node **22+**
4. ตั้ง Environment Variables:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_PUBLISHABLE_KEY` (หรือ anon public key)
   - `VITE_AUTH_MODE=username`
5. ตั้ง Supabase Site URL/Redirect URLs เป็นโดเมนจริง
6. หากแก้ตัวแปรบน Vercel ให้ redeploy เพื่อสร้าง frontend ใหม่

ถ้ายังไม่ตั้ง public config เว็บจะปิดการสมัครและแสดงว่าระบบบัญชียังไม่พร้อม

## ถ้าต้องการเปลี่ยนเป็นอีเมลในอนาคต

ตัวแอปรองรับ `VITE_AUTH_MODE=email` พร้อมสมัคร/ยืนยันอีเมล, ลืมรหัสผ่าน, PKCE recovery และตั้งรหัสผ่านใหม่ ต้องตั้ง Custom SMTP ใน Supabase, เปิด `auth.email.enable_confirmations=true` และ redeploy ก่อนเปิดโหมดนี้ ระบบชื่อผู้ใช้เดิมกับอีเมลเป็นคนละตัวระบุ ไม่ได้ย้ายบัญชีให้เอง

PKCE email links ให้เปิดในเบราว์เซอร์เดียวกับที่ขอส่งลิงก์ การส่งอีเมลเริ่มต้นของ Supabase จำกัดเฉพาะที่อยู่ในทีม ไม่เพียงพอสำหรับเปิดสมัครทั่วไป: [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

## กติกาคำนวณ

GPA = ผลรวมแต้มเกรด × หน่วยกิต / หน่วยกิตที่มีเกรด A ถึง F โดย A=4, B+=3.5, B=3, C+=2.5, C=2, D+=1.5, D=1, F=0; S/U/W/I/ยังไม่ระบุเกรดไม่รวม GPA หน่วยกิตผ่านนับ A–D และ S

รายวิชาซ้ำคิดแยกตามรายการ ไม่แทนเกรดเดิมโดยอัตโนมัติ ต้องตรวจนโยบายคณะก่อนใช้เป็นผลการเรียนทางการ ขั้นต่ำรายหมวดจากภาพรวม 137 แต่หัวภาพระบุ 138 จึงเปิดให้แก้เกณฑ์และตรวจสองส่วนแยกกัน การจัดหมวดและรายการที่ยังไม่ทราบหน่วยกิตต้องตรวจอีกครั้ง

รหัสผ่าน 4–5 ตัวถูกแปลงเป็น SHA-256 แบบมี version/domain prefix ก่อนส่ง Supabase ซึ่ง API กำหนดขั้นต่ำ 6 ตัว จากนั้น Supabase จะ hash สำหรับจัดเก็บตามปกติ รหัสตั้งแต่ 6 ตัวขึ้นไปส่งแบบเดิมเพื่อให้บัญชีเก่าใช้ต่อได้ การแปลงนี้ไม่ได้เพิ่มความแข็งแรงของรหัสที่ผู้ใช้เลือก

เป้าเกียรตินิยมใช้เกณฑ์ตัวเลขที่ผู้ใช้ระบุ ไม่ใช่การรับรองสิทธิ์เกียรตินิยม หน่วยกิตที่เหลืออัตโนมัตินับเฉพาะเกรดว่าง/I ตามแผนที่กรอก S/U/W ไม่คิดเกรด F ที่กรอกแล้วนับใน GPAX โดยไม่เดาการลงซ้ำ ไม่มีการใช้หน่วยกิตจบทั้งหมดแทนหน่วยกิตที่คิดเกรด

## GenEd และ S/U

GenEd บังคับผ่าน 4 รายวิชาในศึกษาทั่วไป เป็นเงื่อนไขจำนวนวิชาแยกจากเกณฑ์หน่วยกิต ปรับจำนวนได้ในเกณฑ์หลักสูตร และเลือกว่าวิชาใดเป็น GenEd ได้ในหน้าต่างแก้ไขวิชา

เลือก S หรือ U ได้โดยตรงจากช่องเกรดของทุกวิชา ไม่มีหัวข้อ ตัวกรอง หรือวิธีประเมินผล S/U แยก S นับหน่วยกิตผ่านในหมวดเดิมครั้งเดียว U ไม่นับผ่าน และ S/U ไม่คิด GPA ส่วนเกรดว่าง/I ถือว่ายังรอเกรดสำหรับการคำนวณเป้าเกียรตินิยมจนกว่าจะเลือกผลการเรียนจริง

แผนเก่าจะเติม metadata ให้รายการ GenEd ที่รู้จัก และเลิกใช้ gradingMode โดยไม่เปลี่ยนเกรดที่ผู้ใช้กรอกไว้แล้ว หน่วยกิตที่ยังไม่ทราบยังทำเครื่องหมายรอตรวจ ไม่เดาตัวเลข

## ปิดตาวิชา (ไม่นับในการคำนวณ)

กดไอคอนตาท้ายวิชาเพื่อยกเว้นจาก GPA/GPAX หน่วยกิตในแผนและที่ผ่าน ความครบหมวด GenEd และหน่วยกิตที่เหลืออัตโนมัติสำหรับเป้าเกียรตินิยม การ์ดสีจางยังอยู่ให้เปิดตากลับได้ เกรด หน่วยกิต ชื่อ รหัส หมวด เทอมและโน้ตยังอยู่ครบ

เพิ่มเพียงฟิลด์ `hidden` แบบ optional ที่วิชาที่ผู้ใช้กดเท่านั้น บัญชีเดิมที่ไม่มีฟิลด์นี้ยังนับทุกวิชาเหมือนเดิม ไม่มีการ reset บัญชีหรือ migration เพื่อซ่อนวิชา สถานะเซฟตามบัญชีและไปกับ JSON backup การแก้ไขวิชาจะเก็บฟิลด์นี้และข้อมูลอื่นเดิมไว้ด้วย

จำนวนหน่วยกิตที่ผู้ใช้กำหนดเองในเป้าเกียรตินิยมเป็นการจำลองแยกต่างหากและคงค่าเดิม หากต้องการให้เปลี่ยนตามวิชาที่ปิดตา ให้เลือกใช้จำนวนตามแผน

## ตัวช่วยลงเพิ่มเพื่อยก GPAX

ใช้ GPAX ท้ายแผน (ค่าเริ่มต้นปี 4 เทอม 2; ถ้าเพิ่มเทอมจะใช้เทอมท้ายสุด) จากคะแนนรวมถ่วงหน่วยกิตจริง หากยังมีเกรดว่าง/I จะใช้เกรดเฉลี่ยที่เลือกเพื่อประมาณการ ไม่มีการถือ 138 เป็นเพดานจำนวนหน่วยกิต

เลือกเกรดเฉลี่ยของวิชาที่จะลงเพิ่ม แล้วดูจำนวนหน่วยกิตที่ต้องเพิ่มอีกเพื่อถึง 3.60/3.25 หรือใส่จำนวนหน่วยกิตเพิ่มเติมเพื่อลองดูผลก่อน จำนวนขั้นต่ำคำนวณจาก `(เป้า × หน่วยกิตฐาน − คะแนนฐาน) / (เกรดเฉลี่ยที่จะเพิ่ม − เป้า)` และปัดขึ้น หากเกรดที่เพิ่มไม่สูงกว่าเป้าขณะ GPAX ยังต่ำกว่าเป้า จะบอกว่าเกรดนี้ดึงถึงเป้าไม่ได้ ไม่แสดงจำนวนที่เป็นไปไม่ได้

การจำลองไม่แก้ไขเกรดหรือเพิ่มรายวิชาอัตโนมัติ วิชา S/U/W และปิดตาไม่คิด GPAX ค่าจำนวนหน่วยกิตคงเหลือแบบเก่ายังอ่านข้อมูลได้ แต่ตัวช่วยใหม่ยึดหน่วยกิตที่รอเกรดจากรายวิชาจริงในแผน

## แผนแนะนำอัตโนมัติ

ตัวช่วยปัจจุบันเลือกเพียงเป้า 3.60/3.25 แล้วจัดแผนให้ ไม่ต้องเลือกเกรดหรือกรอกจำนวนที่จะลงเพิ่มก่อน เริ่มจาก GPAX ที่มีผลเกรดจริง ถ้ามีวิชารอเกรด ให้ลองใช้วิชาในแผนก่อน พร้อมแนะนำการกระจาย A/B+ ตามน้ำหนักหน่วยกิต หากจำเป็นต้องเพิ่ม จะแสดงจำนวนวิชา วิชาละ 3 หน่วยกิต หน่วยกิตรวม และเกรดเป้าหมายของแต่ละกลุ่ม

กรณีต้องเพิ่มมีแผน A ล้วน (เพิ่มน้อยที่สุดในวิชา 3 หน่วยกิต), เผื่อ B+ หนึ่งวิชา และแผนผสม A/B+ หรือ B+ ล้วนเมื่อเกณฑ์ต่ำกว่า 3.50 ค่า GPAX คาดการณ์แสดงในแต่ละแผนแยกจาก GPAX จริงเสมอ ค่า simulation ที่เคยบันทึก เช่น extraCredits=108 ไม่ทำให้แสดงว่าเกรดจริงถึงเกณฑ์แล้ว และไม่เปลี่ยนข้อมูลเดิม
